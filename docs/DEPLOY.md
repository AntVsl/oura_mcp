# Развёртывание на сервере

Как поднять MCP на своём хосте и подключить его к claude.ai, включая айфон.
Общий обзор вариантов запуска — в [README.ru.md](../README.ru.md#запуск);
здесь пошаговый порядок и то, что выясняется только на живом сервере.

## Что нужно заранее

- Хост с Docker и Docker Compose v2. Памяти хватает 1 ГБ: образ тянется
  готовым с Docker Hub, на месте ничего не собирается.
- Имя, по которому сервер будет доступен снаружи, — см. «Вход снаружи».
- `OURA_MCP_TOKEN` — общий секрет эндпоинта.
- Пройденный локально OAuth: `tokens.json` переносится на сервер файлом.

## 1. Файлы и секреты

```bash
ssh root@СЕРВЕР 'mkdir -p /opt/oura-mcp'
scp compose.server.yml compose.caddy.yml compose.tunnel.yml Caddyfile root@СЕРВЕР:/opt/oura-mcp/
```

`.env` создаётся **на сервере**, а не копируется с рабочей машины. Локальный
`.env` содержит `OURA_TOKEN_STORE`, указывающий на `.oura/tokens.json`, — путь,
которого внутри контейнера нет. `compose.server.yml` перекрывает эту переменную
принудительно, но полагаться на это как на единственную защиту не стоит.

```bash
ssh root@СЕРВЕР 'cd /opt/oura-mcp && umask 077 && cat > .env <<EOF
OURA_API_MODE=production
OURA_TZ=Europe/Moscow
OURA_PUBLIC_URL=https://ИМЯ
OURA_CLIENT_ID=<из developer.ouraring.com>
OURA_CLIENT_SECRET=<оттуда же>
OURA_MCP_TOKEN=$(python3 -c "import secrets;print(secrets.token_urlsafe(32))")
EOF'
```

`OURA_PUBLIC_URL` включает OAuth для claude.ai — см. шаг 5. Без него сервер
работает по-старому, на одном общем секрете: этого хватает для Claude Code, но
не для веба и телефона.

Часовой пояс на сервере задать обязательно: системный там UTC, и без него
«сон за сегодня» вернёт не ту ночь.

Отладочный прогон стоит сделать на `OURA_API_MODE=sandbox` — синтетические
данные Oura, настоящие токены не нужны. Так проверяется весь путь, не расходуя
одноразовый refresh-токен.

## 2. Вход снаружи

MCP сам наружу не смотрит: порт 8000 остаётся внутри сети Docker. Вход
выбирается вторым compose-файлом, и выбор не косметический.

### Caddy — прямой вход

```bash
docker compose -f compose.server.yml -f compose.caddy.yml up -d
```

Нужна A-запись на этот сервер **до** первого запуска, иначе проверка Let's
Encrypt не пройдёт. Домена нет? Подойдёт `sslip.io`: имя вида
`203.0.113.10.sslip.io` резолвится в зашитый в него адрес без какой-либо
настройки.

Цена: сертификат попадает в Certificate Transparency — публичный лог, который
индексируется и ищется. С именем от `sslip.io` в лог уходит буквально IP
сервера. **Если на хосте живёт VPN, этот вариант его выдаёт.**

### Cloudflare Tunnel — вход без открытых портов

```bash
docker compose -f compose.server.yml -f compose.tunnel.yml up -d
```

`cloudflared` держит исходящее соединение к Cloudflare. Портов наружу не
открывается вообще, сертификатом владеет Cloudflare, IP сервера в CT-лог не
попадает и снаружи не виден. Ради этого туннель и берётся.

Требует домен в зоне Cloudflare — `sslip.io` в чужой аккаунт не добавить.
Туннель создаётся в панели (Zero Trust → Networks → Tunnels), там же задаётся
маршрут на `http://oura-mcp:8000`; в `.env` кладётся выданный
`CLOUDFLARE_TUNNEL_TOKEN`.

Цена другая: трафик расшифровывается на стороне Cloudflare. Для медданных это
осознанный размен, а не мелочь.

Быстрый туннель (`trycloudflare.com`, без домена и аккаунта) для этого не
годится: имя случайное и меняется при каждом рестарте, а URL коннектора должен
быть постоянным.

## 3. Проверка

```bash
curl https://ИМЯ/healthz                                  # ok, без токена
curl -o /dev/null -w '%{http_code}\n' -X POST https://ИМЯ/mcp   # 401
```

`/healthz` намеренно открыт и не отдаёт данных — он нужен оркестратору.
Всё остальное без верного `Authorization: Bearer` отвечает `401`.

## 4. Перенос авторизации Oura

Флоу OAuth требует браузера и loopback-редиректа, поэтому проходится локально,
а результат переносится файлом:

```bash
scp .oura/tokens.json root@СЕРВЕР:/opt/oura-mcp/tokens.json
ssh root@СЕРВЕР 'docker run --rm -v oura-mcp_oura-data:/data -v /opt/oura-mcp:/src alpine \
  sh -c "cp /src/tokens.json /data/tokens.json && chown 1000 /data/tokens.json && chmod 600 /data/tokens.json" \
  && rm /opt/oura-mcp/tokens.json \
  && docker compose -f /opt/oura-mcp/compose.server.yml restart'
```

`chown 1000` обязателен: контейнер работает не от root, и без него токены не
перезапишутся при обновлении.

> **Refresh-токен Oura одноразовый.** Обновление аннулирует прежний, поэтому
> живой экземпляр должен быть **ровно один**. Как только сервер сделает первый
> запрос, локальная копия `tokens.json` станет недействительной — поэтому
> локальный Claude Code сразу после этого переключается на сервер (шаг 6), а не
> остаётся на stdio.

## 5. claude.ai, включая айфон

Коннектор заводится один раз в веб-интерфейсе и после этого доступен во всех
клиентах Claude одного аккаунта — на айфоне в том числе. Отдельной настройки на
телефоне нет, и добавлять коннектор из мобильного приложения не требуется.

Подключение идёт через **OAuth 2.1** — сервер умеет быть сервером авторизации
сам. Статический заголовок claude.ai тоже понимает, но поле для него
(`static_headers`) в beta с ограниченной раскаткой, и в диалоге его может
просто не быть; у нас его не было. OAuth работает у всех.

**Включается публичным адресом.** В `.env` на сервере:

```
OURA_PUBLIC_URL=https://ИМЯ
```

Без хвостового слэша и обязательно `https` — сервер откажется стартовать с
`http`, потому что по этому адресу ходят коды авторизации и токены. Адрес
попадает в метаданные OAuth, и поле `resource` должно совпасть с тем, что
введено в claude.ai, посимвольно.

**В браузере** (Settings → Connectors → Add custom connector): URL
`https://ИМЯ/mcp`, ровно с путём `/mcp`. Ни client_id, ни секрет вводить не
надо — Claude регистрируется сам через Dynamic Client Registration.

Дальше Claude уведёт в браузер на страницу согласия. Она спросит **тот же
`OURA_MCP_TOKEN`** — второго пароля здесь нет намеренно: владелец один, и
лишний секрет пришлось бы отдельно хранить, менять и терять.

**На айфоне**: коннектор заводится один раз в вебе и после этого доступен во
всех клиентах Claude одного аккаунта. Отдельно на телефоне настраивать нечего —
открыть приложение, в чате нажать «+» → Connectors и включить в разговоре.
Страница согласия свёрстана под телефон: если подключаешь прямо с айфона,
менеджер паролей предложит сохранить секрет.

> Что происходит под капотом, если понадобится отлаживать:
>
> ```
> /.well-known/oauth-protected-resource/mcp   кто защищает ресурс
> /.well-known/oauth-authorization-server     где authorize, token, register
> /register    Claude регистрируется публичным клиентом (секрет не выдаётся)
> /authorize   уводит на /oauth/consent
> /token       обмен кода; refresh ротируется, старый умирает
> ```
>
> Ответ `401` на `/mcp` несёт `WWW-Authenticate` с `resource_metadata` — по
> нему Claude и находит метаданные, без лишних попыток угадать адрес.

**Claude Code при этом ничего не теряет.** Общий секрет продолжает работать как
бессрочный токен — см. шаг 6. Два пути расходятся внутри одной проверки, так
что настройка из шага 6 переживёт включение OAuth.

## 6. Claude Code с любой машины

```bash
claude mcp add --scope user --transport http oura https://ИМЯ/mcp --header "Authorization: Bearer ТОКЕН"
```

Если раньше сервер был подключён по stdio, старую запись надо удалить
(`claude mcp remove oura`): два экземпляра с общим хранилищем токенов выбьют
друг друга из авторизации.

## Эксплуатация

```bash
cd /opt/oura-mcp
docker compose -f compose.server.yml logs -f --tail 50   # логи
docker compose -f compose.server.yml pull && \
  docker compose -f compose.server.yml up -d              # обновление
```

Откат — поднять с прежним тегом: `OURA_TAG=0.1.0` в `.env`.

Автообновление намеренно выключено: у контейнера нет метки watchtower. Релиз
сервера с медданными должен быть решением, а не побочным эффектом появления
нового тега.

Заголовок `Authorization` вычищается из логов Caddy — см. [Caddyfile](../Caddyfile).
