# Агентская разработка

Эта папка делает работу нескольких агентов проверяемой и безопасной, не
привязывая репозиторий к одному клиенту. Корневой
[AGENTS.md](../../AGENTS.md) — обязательные инструкции для Codex и других
кодовых агентов; здесь лежат шаблоны и порядок совместной работы.

## Цикл задачи

1. Перед началом сохранить короткий бриф по
   [task-template.md](task-template.md): цель, границы файлов, риски и
   критерии приёмки.
2. Один агент владеет каждым изменяемым файлом. Если задача пересекается с
   другой, сначала разделить файлы или передать изменение владельцу.
3. Реализация должна включать тест либо явное объяснение, почему поведение
   невозможно проверить автоматически.
4. Ревьюер использует [review-template.md](review-template.md): сначала
   безопасность и обратная совместимость, затем код, тесты и документация.
5. Перед передачей выполнить `uv lock --check`, `uv run pytest -q` и
   `git diff --check`; в отчёте зафиксировать их результат.

## Карта клиентов

| Клиент | Транспорт | Авторизация | Что проверять при изменении |
| --- | --- | --- | --- |
| Claude Code | stdio или HTTP | локально нет; удалённо Bearer | команда `claude mcp add` |
| Claude.ai | публичный HTTP | OAuth/DCR | origin `https://claude.ai`, consent |
| Codex | stdio или HTTP | локально нет; удалённо Bearer или OAuth | команда `codex mcp add` |
| ChatGPT | только публичный HTTP | OAuth/DCR | origin `https://chatgpt.com`, сканирование tools |

ChatGPT не умеет подключаться к локальному процессу напрямую, поэтому URL для
него обязан быть публичным и HTTPS. `OURA_OAUTH_ALLOWED_REDIRECT_ORIGINS`
является allowlist: добавление origin — изменение политики доступа и требует
явного ревью.

## Границы параллельной работы

- Безопасно параллелить: независимые тесты, исследование документации,
  подготовку разных файлов в `docs/`.
- Нельзя параллельно редактировать: `config.py`, OAuth-провайдер, `server.json`,
  `uv.lock`, README и один тестовый файл без назначенного владельца.
- Перед интеграцией всегда перечитать `git diff` целиком: агент может увидеть
  изменения другого агента в общей рабочей директории.

## Минимальный набор доказательств

Для изменения кода — тесты, которые упали бы до исправления. Для конфигурации
или OAuth — тест разбора и тест wiring. Для документации по клиенту — команда
или экранный путь, проверенный по первичному руководству клиента, и ссылка на
него. Для релизных файлов — проверка согласованности версии.
