# Roadmap

Что сделано, что отложено и почему. Файл живёт в репозитории, чтобы
договорённости не терялись между сессиями.

## Сделано

- **Сервер и инструменты.** 11 инструментов, нарезанных по вопросам, а не по
  эндпоинтам Oura. Сжатая сводка по умолчанию, сырой JSON по `raw=True`.
- **Клиент.** Обход пагинации `next_token`, ретраи с экспоненциальным бэкоффом,
  перевод кодов ответа в сообщения, по которым понятно, что чинить.
- **OAuth2.** Разовый вход через браузер, атомарное хранение токенов с правами
  `600`, автоматическое обновление, сериализация параллельных обновлений.
- **Два транспорта.** `stdio` и `streamable-http` из одного кода.
- **Защита HTTP-эндпоинта.** Общий секрет, сравнение постоянного времени, отказ
  стартовать на внешнем адресе без секрета.
- **Docker.** Образ и `compose.yml` с Caddy, проверены запуском.
- **Часовые пояса.** Пять багов, из-за которых данные пропадали молча —
  см. «Уроки» ниже.
- **Публикация.** [PyPI](https://pypi.org/project/my-oura-mcp/) (`uvx my-oura-mcp`)
  и [Docker Hub](https://hub.docker.com/r/iican/oura-mcp) (`latest`, `0.1`,
  `0.1.0`, amd64 + arm64). Оба артефакта проверены установкой и запуском, а не
  фактом «CI зелёный».
- **CI.** Тесты на 3.12 и 3.13, проверка метаданных пакета, сборка образа под
  обе архитектуры без публикации. Релиз запускается тегом и сверяет его с
  версией в `pyproject.toml`.
- **Свой сервер авторизации OAuth 2.1.** Единственный способ подключить
  claude.ai с личного тарифа: поля для статического заголовка в диалоге нет.
  Протокол не писали — он весь в официальном SDK (`mcp.server.auth`): PKCE
  S256, сроки жизни, сверка `redirect_uri`, DCR. Своё — только политика и
  хранение, около 150 строк и 19 тестов.

  Ключевое решение: общий секрет работает **бессрочным access-токеном внутри
  провайдера**, а не отдельным слоем. Иначе получались два взаимоисключающих
  привратника, и статический токен, пройдя свой, упирался бы в OAuth-middleware
  SDK. Так путь один, а Claude Code и claude.ai расходятся в одной функции.

  Одна заплатка на SDK: он зашивает `token_endpoint_auth_methods_supported`
  константой без `"none"`, хотя публичных клиентов обслуживает правильно —
  расходятся объявление и поведение, а Claude при DCR приходит именно
  публичным клиентом. Своим маршрутом это не перебить (маршруты SDK
  регистрируются раньше и Starlette отдаёт запрос первому совпавшему,
  проверено запуском), поэтому ASGI-middleware **дописывает** одно поле в
  готовый ответ, а не подменяет документ: подмена молча теряла бы поля,
  которые SDK добавит позже.

## Дальше

### Развёртывание на сервере

Единственный путь к исходной цели: Oura в веб-интерфейсе claude.ai с любого
устройства. Через каталоги туда не попасть — см. «Не планируется» ниже, — так
что остаётся только свой сервер.

`compose.yml`, `Dockerfile` и `Caddyfile` готовы и проверены локально, образ
опубликован (`iican/oura-mcp`), но на настоящем сервере ничего не запускалось.
Нужны: сервер с публичным IP, домен с A-записью, `OURA_MCP_TOKEN`, подключение
claude.ai через Request headers.

Токены OAuth придётся перенести на сервер отдельно: флоу требует браузера и
loopback-редиректа, поэтому проходится локально, а `tokens.json` кладётся в
том `/data`. И помнить про одноразовость refresh-токена — держать один живой
экземпляр, а локальный Claude Code после подъёма сервера переключить на него.

Отдельно стоит помнить: **не разворачивать на том же хосте, где живёт VPN** —
публичный HTTPS-домен портит репутацию IP и привлекает к нему внимание.

Вопрос про аутентификацию закрыт, и не в ту сторону, на которую рассчитывали:
раздела **Request headers** в диалоге не оказалось — раскатка beta до нас не
дошла. Поэтому сервер авторизации написан свой, см. «Сделано».

Что осталось непроверенным — сам флоу против claude.ai. Всё, что можно было
проверить без домена, проверено запуском; подключение с телефона — нет.

## Отложено

### Кэш SQLite

Прошедшие дни в Oura неизменяемы, поэтому их можно класть в локальную базу и
больше не запрашивать. Даёт два выигрыша: длинные периоды (полгода трендов
вместо недели) перестают быть сотнями обращений к API, и работа становится
устойчивой к обрывам сети.

Отложено осознанно: улучшает то, чем пользуется один человек, а публикация
была разовой работой, которую дешевле было сделать по свежим следам. Теперь
очередь за кэшем — но после развёртывания, иначе придётся делать его дважды.

Что понадобится: таблица по (эндпоинт, день), запись только завершённых суток
(сегодняшний день кэшировать нельзя — данные ещё дописываются), инвалидация по
запросу, путь к базе уже есть в `OURA_CACHE_DB`.

### MCP Resources

Сейчас сервер отдаёт только инструменты. Протокол поддерживает ещё и ресурсы —
их клиент может подтянуть в контекст сам, без вызова функции. Для «сводки за
сегодня» это естественнее: модели не приходится решать, какой инструмент
позвать и с какими аргументами.

Идея подсмотрена у `pokidyshev/oura-mcp`, где ресурсов пять: сегодняшняя
сводка, вчерашняя, личные данные, недавние тренды сна и активности.

Что оттуда брать не стоит — разбор дат на естественном языке («today», «last
week»). В MCP это лишний слой: модель и так переводит «за прошлую неделю» в
`days_back=7`, для того она и стоит между человеком и инструментом.

## Не планируется

### Публикация в реестр MCP

`server.json` готов и соответствует схеме, требование реестра «артефакт уже
опубликован» выполнено дважды (PyPI и Docker Hub). Технически осталось
`mcp-publisher login github` и `mcp-publisher publish`. Тем не менее публикация
не планируется, и вот почему.

**Открытый реестр и каталог коннекторов claude.ai — разные каталоги, между
собой не связанные.** Это легко перепутать, и мы перепутали.

`registry.modelcontextprotocol.io` — community-проект самого протокола: API с
метаданными, куда публикуется кто угодно, подтвердив пространство имён через
GitHub. Каталог в claude.ai — собственный каталог Anthropic с отдельным
порталом подачи. Документация Anthropic говорит прямо: подтверждение владения
доменом «требуется только для открытого реестра MCP, но не для каталога
Anthropic». Публикация в первом не даёт ничего во втором.

Попасть в каталог claude.ai мешает не качество сервера, а тариф: подача
**требует организации Team или Enterprise** и права управления каталогом. С
личного тарифа заявку не подать в принципе.

Что до самого открытого реестра — практическая отдача сегодня мала.
Большинство MCP-клиентов его не читают, подключая серверы вручную через
конфиг. Модерации нет: по запросу «oura» находится восемь записей, из которых
одна продублирована четыре раза, плюс три зеркала одного сервера. Реальная
видимость сводится к агрегаторам, которые реестр индексируют.

**Для доступа из claude.ai каталог не нужен вообще.** «Add custom connector» с
URL своего сервера и заголовком `Authorization` работает независимо от любых
каталогов — разница лишь в том, что подключаешь сам, а не выбираешь из списка.
Поэтому путь к цели «Oura в веб-интерфейсе с любого устройства» — это
развёртывание на сервере, а не публикация куда-либо.

## Уроки

Пять багов проекта имеют общую природу: **данные пропадали без ошибки**. Ни
исключения, ни предупреждения — просто пустой ответ или подменённая запись, и
статистика тихо врала. С внешним API тихий пустой ответ опаснее упавшего
запроса, поэтому:

- диапазоны дат разрешаются в заданном поясе, а не в системном;
- `sleep` и `daily_activity` Oura фильтрует по метке времени в UTC, а не по
  полю `day`, которое сама же возвращает — окно расширяется, лишнее
  отсекается на нашей стороне;
- `heartrate` отдаёт `timestamp` в UTC, и группировать его надо по местному
  поясу, иначе ночной пульс уезжает в предыдущие сутки;
- за сутки Oura отдаёт несколько записей сна — основную ночь надо выбирать
  явно, а не брать произвольную;
- тесты инструментов идут через `mcp.call_tool()`, а не прямым вызовом
  функций: MCP-клиент подставляет объявленные умолчания как явные аргументы, и
  целый класс багов виден только на настоящем протокольном слое.
