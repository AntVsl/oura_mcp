# my-oura-mcp

*Русская версия. Основной README — [английский](README.md).*

Даёт Claude доступ к данным твоего кольца Oura: сон, готовность, HRV, пульс
покоя, активность, SpO₂, стресс.

Спрашиваешь «как я спал на прошлой неделе» — Claude сам вызывает нужный
инструмент и получает готовую сводку, а не гору JSON:

```json
{
  "metric": "sleep_detail",
  "period": { "start": "2026-07-23", "end": "2026-07-29", "days": 7 },
  "stats": {
    "total_h":    { "mean": 7.1, "min": 5.9, "max": 8.4 },
    "deep_h":     { "mean": 1.3, "min": 0.9, "max": 1.8 },
    "avg_hrv":    { "mean": 42,  "min": 31,  "max": 55, "trend_per_week": 1.8 },
    "efficiency": { "mean": 88,  "min": 82,  "max": 93 }
  }
}
```

> **Что такое MCP?** Model Context Protocol — способ дать Claude доступ к
> внешним данным. Ставишь такой сервер, подключаешь один раз, и дальше просто
> спрашиваешь Claude про свой сон обычными словами. Программировать ничего не
> надо.

Работает и в Claude Code в терминале, и в claude.ai — включая приложение на
телефоне, если развернуть на своём сервере.

## Быстрый старт

Попробовать можно за минуту: сервер умеет работать на тестовых данных Oura, и
на этом шаге ни кольцо, ни токен не нужны.

Понадобится [uv](https://docs.astral.sh/uv/) — менеджер окружений для Python.

```bash
git clone https://github.com/AntVsl/oura_mcp && cd oura_mcp
cp .env.example .env
uv sync
```

Проверка, что данные доходят:

```bash
uv run python -m my_oura_mcp.smoke
```

Подключение к Claude Code — команду с уже подставленным абсолютным путём
подскажет сам сервер:

```bash
uv run my-oura-mcp install
```

Он печатает готовое к вставке для Claude Code, Claude Desktop и Cursor и
**ничего не записывает**: дописываться в чужие конфиги мы не стали, потому что
цена ошибки там платится не нами.

Дальше просто спроси в сессии: *«покажи сводку Oura за неделю»*. Инструмент
`get_status` подскажет, на тестовых данных сервер или на твоих.

Как перейти на свои данные — в разделе [«Переход на реальные
данные»](#переход-на-реальные-данные).

## Особенности

- **Ответы сжаты заранее.** Вместо сырого ответа API возвращается сводка:
  значения по дням плюс средние, минимумы, максимумы и тренд. Это и дешевле по
  контексту, и модели проще на этом рассуждать. Полный ответ доступен через
  `raw=True` у любого инструмента.
- **Инструменты нарезаны по вопросам, а не по эндпоинтам Oura.** «Как я спал»
  и «готов ли я к нагрузке» — разные инструменты, хотя данные частично из
  одного места.
- **Работает локально и на сервере из одного кода.** Локально — рядом с Claude
  Code, на сервере — по HTTP, чтобы дотянуться из claude.ai и с телефона.
  Разница в одном флаге при запуске.
- **Аккуратен к часовым поясам.** Oura отдаёт часть данных в UTC, и наивная
  обработка молча теряет ночи или сдвигает ночной пульс на сутки. Здесь это
  разобрано — см. [«Уроки»](docs/ROADMAP.md) в roadmap.
- **Не падает от сети.** Постранично забирает длинные периоды, повторяет
  запросы при обрывах и переводит коды ответа в сообщения, по которым понятно,
  что чинить.

## Инструменты

| Инструмент | Что отдаёт | По умолчанию |
|---|---|---|
| `get_daily_summary` | Оценки сна, готовности и активности сразу | 7 дней |
| `get_sleep` | Стадии сна, эффективность, HRV, пульс покоя, дыхание, температура | 7 дней |
| `get_sleep_score` | Только дневная оценка сна — легче, чем `get_sleep` | 7 дней |
| `get_readiness` | Готовность, баланс HRV, отклонение температуры | 7 дней |
| `get_activity` | Оценка активности, шаги, калории | 7 дней |
| `get_heartrate` | Поминутный пульс, свёрнутый посуточно | 3 дня |
| `get_spo2` | SpO₂ во сне, индекс нарушений дыхания | 7 дней |
| `get_stress` | Время под нагрузкой и в восстановлении | 7 дней |
| `get_heart_health` | Сосудистый возраст, VO₂max | 30 дней |
| `get_tags` | Отметки, проставленные вручную в приложении | 30 дней |
| `get_status` | Режим работы и состояние авторизации | — |

Общие параметры: `days_back` **либо** пара `start_date`/`end_date`
(`YYYY-MM-DD`), плюс `raw` для получения нетронутого ответа Oura.

## Переход на реальные данные

Песочница отдаёт синтетику. Чтобы получить свои данные, нужно приложение Oura
и разовая авторизация.

**1. Зарегистрируй приложение** на
[developer.ouraring.com/applications](https://developer.ouraring.com/applications):

| Поле | Значение |
|---|---|
| Redirect URI | `http://localhost:8765/callback` — сверяется посимвольно |
| Scopes | `daily`, `heartrate`, `tag`, `spo2`, `stress`, `heart_health` |
| Остальные поля | произвольные; для персонального приложения не проверяются |

Проходить ревью не нужно: свежее приложение работает сразу, лимит — 10
пользователей.

**2. Впиши `OURA_CLIENT_ID` и `OURA_CLIENT_SECRET` в `.env`.**

**3. Пройди авторизацию** — один раз:

```bash
uv run my-oura-mcp auth
```

Команда поднимет локальный сервер на адресе из `OURA_REDIRECT_URI`, откроет
браузер и после подтверждения сохранит токены в `.oura/tokens.json` (права
`600`). Дальше сервер обновляет их сам.

**4. Переключи `OURA_API_MODE=production`** в `.env`.

Вспомогательное:

```bash
uv run my-oura-mcp auth --status   # авторизован ли, сколько живёт токен
uv run my-oura-mcp auth --logout   # забыть токены
```

> Personal Access Token больше не подойдёт: Oura прекратила их выпуск в декабре
> 2025, доступ только через OAuth2.

> **Refresh-токен одноразовый.** При каждом обновлении Oura выдаёт новый и
> аннулирует прежний, поэтому два сервера с общим хранилищем выбьют друг друга
> из авторизации. Признак — `400` с сообщением про одноразовость: лечится
> повторным `my-oura-mcp auth` и переходом на один живой экземпляр.

## Конфигурация

Всё через `.env` (см. `.env.example`). Секреты в git не попадают.

| Переменная | Назначение |
|---|---|
| `OURA_CLIENT_ID` / `OURA_CLIENT_SECRET` | Учётные данные приложения Oura |
| `OURA_REDIRECT_URI` | Должен совпадать с указанным в приложении |
| `OURA_API_MODE` | `sandbox` (тестовые данные) или `production` |
| `OURA_TZ` | Часовой пояс для трактовки «сегодня». **На сервере задать явно** |
| `OURA_TOKEN_STORE` | Куда OAuth-флоу пишет токены. Руками не заполняется |
| `OURA_CACHE_DB` | Файл кэша SQLite. Пустое значение выключает кэш |
| `OURA_MCP_TOKEN` | Общий секрет HTTP-эндпоинта. Он же пароль на странице согласия |
| `OURA_PUBLIC_URL` | Публичный `https`-адрес. Задан — включается OAuth для claude.ai |

Почему `OURA_TZ` важен: на хосте в UTC системное «сегодня» отличается от твоего,
и запрос «сон за вчера» вернёт не ту ночь.

## Запуск

Один и тот же код обслуживает оба сценария — различается только транспорт.

### Локально: Claude Code на этой машине

```bash
claude mcp add --scope user oura -- uv --directory /путь/к/oura_mcp run my-oura-mcp
```

`--scope user` делает сервер видимым из любого каталога; без него он
подключится только в той папке, где выполнена команда. Проверка:

```bash
claude mcp list
```

Транспорт stdio, сеть не задействована, ничего наружу не открывается.

### Локально по HTTP: отладка транспорта

```bash
uv run my-oura-mcp --transport http --port 8000
```

На loopback-адресе секрет не требуется. Здесь удобно воспроизводить то, что
потом будет происходить на сервере.

### Глобально: свой сервер, доступ отовсюду

Даёт доступ с любого устройства, из веб-интерфейса claude.ai и с телефона.
Понадобятся сервер с публичным адресом и свой домен.

Подробная инструкция — **[docs/DEPLOY.md](docs/DEPLOY.md)**. Там же выбор входа
снаружи, перенос авторизации Oura на сервер и подключение claude.ai. Здесь
только то, чем этот путь отличается.

Два способа впустить трафик, и выбор не косметический: Caddy с сертификатом
Let's Encrypt проще, но засвечивает адрес сервера в публичном журнале
сертификатов, а Cloudflare Tunnel не открывает портов вовсе. Если на том же
хосте живёт VPN, годится только второй.

Подключение к claude.ai идёт через OAuth, и его включает `OURA_PUBLIC_URL`:
сервер сам становится сервером авторизации с динамической регистрацией
клиентов. Ни client_id, ни секрет в диалоге коннектора вводить не надо — Claude
регистрируется сам, а страница согласия спросит тот же `OURA_MCP_TOKEN`.
Заводится коннектор один раз в вебе и дальше доступен во всех клиентах Claude
одного аккаунта, включая приложение на телефоне.

Claude Code с любой машины подключается заголовком, без всякого OAuth:

```bash
claude mcp add --scope user --transport http oura https://твой-домен/mcp --header "Authorization: Bearer ТВОЙ_ТОКЕН"
```

Без заголовка или с неверным токеном эндпоинт отвечает `401` и до данных не
допускает.

### Что выбрать

| | stdio локально | HTTP на сервере |
|---|---|---|
| Доступ из Claude Code на этой машине | да | да |
| Доступ с других устройств | нет | да |
| Доступ из claude.ai и с телефона | нет | да, через OAuth |
| Нужен домен и сервер | нет | да |
| Данные покидают машину | нет | да, на твой сервер |

Держи **один живой экземпляр**: refresh-токен Oura одноразовый, и два сервера
с общим хранилищем токенов будут выбивать друг друга из авторизации. Подняв
удалённый, переключи на него и локальный Claude Code — вариантом из шага 4.

## Безопасность

- `.env`, хранилище токенов и кэш перечислены в `.gitignore`. Проверяй перед
  коммитом: `git status --porcelain`.
- Refresh-токен Oura **одноразовый** — при каждом обновлении выдаётся новый.
  Два экземпляра сервера с одним токеном будут выбивать друг друга из
  авторизации. Держи один живой инстанс: когда поднимешь удалённый, направляй
  на него и Claude Code.
- HTTP-эндпоинт закрыт общим секретом `OURA_MCP_TOKEN` (сравнение постоянного
  времени). Модель доступа намеренно простая: один секрет, один владелец,
  разграничения между пользователями нет.
- **Сервер не запустится на внешнем адресе без секрета** — вместо тихой отдачи
  медданных в открытый интернет он откажется стартовать. Проверить локально:
  `uv run my-oura-mcp --transport http --host 0.0.0.0`.
- Путь `/healthz` открыт без токена намеренно — он нужен reverse proxy и не
  отдаёт ничего, кроме `ok`.
- Заголовок `Authorization` вычищается из логов Caddy.
- При включённом OAuth (`OURA_PUBLIC_URL`) секрет работает как бессрочный
  access-токен: путь проверки один, и настройки Claude Code с `--header` не
  ломаются. Страница согласия спрашивает тот же секрет, отдаётся с
  `Content-Security-Policy` без права на скрипты и запретом на встраивание в
  iframe, а идентификатор заявки экранируется.
- Refresh-токены OAuth ротируются при каждом обновлении и живут три месяца;
  протухшие вычищаются из хранилища при выдаче новых.

## Кэш

Прошедшие сутки в Oura неизменяемы, поэтому они кладутся в SQLite и больше не
запрашиваются. На повторном запросе за две недели в сеть уходит только
сегодняшний день, а чисто историческое окно обходится вообще без обращений.

```bash
uv run my-oura-mcp cache --status   # что закэшировано
uv run my-oura-mcp cache --clear    # забыть
```

Три вещи, о которых стоит знать. **Сегодня не кэшируется никогда** — Oura ещё
дописывает эти данные. **Пустые дни тоже не кэшируются**: пустота бывает «не
носил кольцо» и «ещё не синхронизировалось», и второе лечится само через
часы — а закэшированная пустота осталась бы навсегда. **Режим входит в ключ**,
так что синтетика из песочницы не всплывёт в production.

Поминутный пульс мимо кэша: у его записей нет поля `day`.

## Навык с рецептами

В [skills/oura](skills/oura) лежит навык для Claude — не инструменты, а
сценарии поверх них: как разобраться, улучшается ли сон, можно ли сегодня
давать нагрузку, что происходило с телом в плохой день, сработало ли изменение
в режиме. Это последовательности вызовов плюс способ рассуждать над ответом,
чего отдельный инструмент выразить не может.

Подключается копированием в каталог навыков клиента:

```bash
cp -r skills/oura ~/.claude/skills/
```

Рецепты сверяются с кодом тестами: имя поля, которого нет в ответе, ловится
на `uv run pytest`, а не молча уводит модель в пустоту.

## Если что-то не работает

**Claude отвечает, что инструментов Oura нет.** Сервер не подключился. Проверь
`claude mcp list` — там видно состояние. Частая причина — относительный путь
вместо полного; `uv run my-oura-mcp install` печатает команду с правильным.

**`Авторизация не пройдена — токенов нет`.** Сервер в режиме `production`, но
вход в Oura не сделан. Запусти `uv run my-oura-mcp auth`. Посмотреть состояние
токенов: `uv run my-oura-mcp auth --status`.

**`401` при обращении к серверу на VPS.** Не совпадает `OURA_MCP_TOKEN`.
Значение заголовка отправляется как есть, поэтому слово `Bearer` и пробел перед
токеном — часть значения: `Bearer abc123`, не `abc123`.

**Данные приходят не за тот день.** Не задан `OURA_TZ`. На сервере системное
время почти всегда UTC, и «сегодня» там начинается на три часа позже
московского — ночной сон уезжает в предыдущие сутки. Пояс указывается явно:
`OURA_TZ=Europe/Moscow`.

**`refresh-токен отвергнут`.** Он одноразовый, и так бывает, когда тем же
токеном воспользовался второй экземпляр сервера. Держи один живой: подняв
сервер на VPS, переключи на него и локальный Claude Code. Лечится повторным
`my-oura-mcp auth`.

**Запросы к `api.ouraring.com` рвутся** с `SSL_ERROR_SYSCALL` или таймаутом.
Дело обычно не в сервере: клиент делает четыре попытки с нарастающей паузой, и
если не помогает — включи VPN.

**claude.ai не подключается к своему серверу.** Проверь, что задан
`OURA_PUBLIC_URL` и совпадает с URL коннектора посимвольно, включая
`https://` и отсутствие слэша на конце. Баннер при запуске сообщает, поднялся
ли OAuth. Дальше — [docs/DEPLOY.md](docs/DEPLOY.md).

**Нажимаешь «Разрешить» на странице согласия, и ничего не происходит.** Смотри
логи сервера: если там `POST /oauth/consent` с кодом `303`, но следом нет
`POST /token`, значит браузер заблокировал переход на claude.ai. Так себя ведёт
слишком строгий `Content-Security-Policy` — проверять это `curl`'ом бесполезно,
он CSP не применяет.

**«Запрос устарел».** Заявки на авторизацию живут в памяти процесса, и
перезапуск сервера их стирает вместе с открытой вкладкой. Секрет тут ни при
чём — надо вернуться в claude.ai и начать подключение заново.

## Разработка

```bash
uv run pytest
```

Тесты идут на зафиксированных ответах и сеть не трогают.

**x86_64 macOS:** `cryptography` с версии 49 не публикует бинарное колесо под
эту платформу и пытается собраться из Rust-исходников. В `pyproject.toml` стоит
прицельное ограничение на `48.0.0`; Linux и нативный arm64 оно не затрагивает.

Это касается не только Intel-машин. Если Homebrew установлен в `/usr/local`
(а не в `/opt/homebrew`), то на Apple Silicon весь Python-стек всё равно
x86_64 и идёт через Rosetta. Проверить: `file $(which python3)`.

**Перебои сети:** если запросы к `api.ouraring.com` рвутся с
`SSL_ERROR_SYSCALL` или таймаутом, дело обычно не в сервере. Клиент делает 4
попытки с бэкоффом; если не помогает — включи VPN.

Что запланировано и что отложено осознанно — в [docs/ROADMAP.md](docs/ROADMAP.md).
